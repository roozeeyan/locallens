## Правила работы нескольких сессий

Над веткой `claude/locallens-content-population-gkCQI` работают несколько
сессий сразу. **Определяй себя по тому, где ты выполняешься, а не по названию
чата** — названия Рузанна меняет, и они уже совпадали у разных сессий.

| Где ты выполняешься | Кто ты | Что пишешь |
|---|---|---|
| Контейнер в облаке (`environment_kind: anthropic_cloud`), браузерных инструментов нет | Облачная рабочая | `src/*.json`, `src/data.js`, `scripts/`, `.github/`, этот файл |
| Мак Рузанны, есть `mcp__claude-in-chrome__*`, папка `/Users/roo/Documents/GitHub/locallens` | Локальная рабочая | `map-exports/`, координаты в `src/coords.json` |
| Чат Cowork на Маке | Cowork | только `map-exports/` |

Все три — **рабочие**. Сессия от 3 июня, которая уткнулась в вопрос
«Takeout (1) или локальная сессия (2)», отправлена в архив 28.09.2026 и
действовать физически не может. Если ты сомневаешься, не архивная ли ты, —
проверь дату создания и статус, а не заголовок.

### Запрещено всем

1. **Не запускай воркфлоу GitHub Actions**, если тебя об этом не попросили
   в этом разговоре прямо сейчас. Скрипты в `scripts/` пишут JSON-файлы
   через GitHub Contents API — это **перезапись файла целиком**, без слияния.
   Запуск со старым состоянием затирает чужую работу молча и полностью.
   В `.claude/settings.json` на это стоит `ask` — подтверждение обязательно.
2. **Не делай `git push --force`** и не переписывай историю ветки.
3. **Не трогай файлы из чужой строки таблицы выше.**
4. **Перед любой записью — `git pull`.** После записи — сразу `push`,
   не накапливай изменения.

### Подводный камень: не все места записаны одинаково

В `src/data.js` **925 мест**, но одно из них — `id: 150`
(`J Space™ Jazzve Urban Hub`) — записано в несколько строк, а не в одну.
Регулярка вида `\{ id: (\d+), cityId: "..."` его **не находит** и даёт 924.
На это уже попались две сессии. Считай места по `\bid:\s*(\d+)` внутри
`INITIAL_PLACES`, либо приводи запись к однострочному виду.

## Проект

**LocalLens** — персональный travel mini-app (locallens-mocha.vercel.app).  
Личная подборка мест от Roo: кафе, рестораны, природа, достопримечательности.  
Репозиторий: `roozeeyan/locallens` · Деплой: Vercel автоматически из ветки `main`.

**Стек:** React 18, CRA (react-scripts/webpack), inline styles (объект `s` в App.jsx), без TypeScript.

**Автоматические фоновые задачи (GitHub Actions по расписанию):**
- Каждый день 06:00 UTC — аудит качества данных (`audit-places.yml`)
- Каждый понедельник 04:00 UTC (08:00 Ереван) — еженедельное обслуживание (`weekly-maintenance.yml`):
  1. Исправление описаний на английском → русский
  2. Перезапись шаблонных/клишированных описаний
  3. Финальный аудит качества

**Доступ защищён паролем:** код `919526` хранится в Vercel env var `REACT_APP_ACCESS_CODE`.

## Структура файлов

```
src/
  App.jsx          — весь UI (один файл, ~1200 строк)
  data.js          — 925 мест, 8 городов (CITIES + INITIAL_PLACES)
  culture.json     — культурные факты по городам (сторис)
  descriptions.json — AI-описания мест {id: "текст"}
  photos.json      — фотографии мест {id: ["url1","url2",...]}
  coords.json      — координаты мест {id: {lat, lng}}
  hours.json       — часы работы мест

scripts/
  generate_descriptions.py   — AI-описания через Groq (llama-3.3-70b-versatile)
  fetch_photos.py            — фото через Serper Image Search API
  fetch_culture_images.py    — фото для культурных фактов с Wikipedia
  fetch_wiki_descriptions.py — описания достопримечательностей с Wikipedia
  fetch_coords.py            — координаты через Nominatim/OSM
  fetch_hours.py             — часы работы
  audit_places.py            — аудит качества данных

.github/workflows/           — GitHub Actions воркфлоу (workflow_dispatch)
```

## Как запускать воркфлоу

GitHub → Actions → выбрать воркфлоу → **Run workflow**.

| Воркфлоу | Назначение | Параметры |
|----------|-----------|-----------|
| `Generate AI Descriptions` | AI-описания через Groq | city, batch, --fix-template |
| `Fetch Culture Images` | Фото для культурных фактов с Wikipedia | — |
| `Fetch Wikipedia Descriptions` | Описания достопримечательностей | city |
| `Fetch Photos` | Фото мест через Serper | city |
| `Fetch Coords` | Координаты через OSM | city |

**Secrets в GitHub:** `GROQ_API_KEY`, `SERPER_API_KEY`, `FOURSQUARE_API_KEY`.

## Ключевые технические решения

- `src/data.js` содержит все места с полями: `id, cityId, category, name, description, photos, coords, hours, badge, district, tags, travelAround, rooChoice`
- `descriptions.json` и `photos.json` мержатся в `INITIAL_PLACES` при инициализации (см. data.js)
- Описания от Groq: запрещены слова «уютный», «расположен», «находится», «в сердце», «в центре», «предлагает»
- Фото: фильтруются BAD_DOMAINS (социальные сети, музыкальные сервисы, wikipedia)
- Пароль: `localStorage.setItem("ll_access", code)` — без re-enter после перезагрузки
